针对 `input_sku_id` 传入格式异常的值（SPU 当 SKU、截断、大小写错误、含空格/连字符等），验证接口的校验行为。

| BV-37 | 截断 SKU（10位） | `A11M627701` | 200 | 0.09s | 0 | ES 查不到 |

| BV-42 | 纯数字 | `1234567890123` | 200 | 0.09s | 0 | ES 查不到 |
| BV-43 | 1 位字符 | `X` | 200 | 0.08s | 0 | ES 查不到 |

**结论与问题：**

- 所有不合法 SKU 均返回 200 + 空 outfits 列表，不报错、不 500
- **大小写敏感**：小写 `a11m627701fpk` 查不到（ES 精确匹配）
- **SKU 格式无校验**：任何长度、任何字符的字符串都会尝试查 ES，查不到返回空

**⚠️ 问题 ISS-02：不合法 SKU 未返回错误码**
- 所有格式异常的 SKU（SPU、截断、小写、含空格/连字符/中文等）均返回 200 + 空列表
- 调用方无法区分"SKU 格式错误"和"SKU 合法但无搭配推荐"
- **建议**：增加 SKU 格式校验（如正则 `^[A-Z]\d{2}[A-Z]\d{6}[A-Z]\d?$`），格式不匹配时返回 400 `invalid sku_id format`

**⚠️ 问题 ISS-03：前后空格 strip 不一致**
- `input_sku_id="  A11M627701FPK  "` → 查 ES 时被 strip（查到 6 套）
- 但响应 `input_sku_id` 原样返回 `"  A11M627701FPK  "`（带空格）
- 调用方可能误以为返回的 sku 与入参完全一致，造成数据不一致
- **建议**：响应中 `input_sku_id` 应返回 strip 后的值

**⚠️ 问题 ISS-01：tryon 字段数字类型自动转换**
- `tryon: 0` → 被当作 false（行为正确但类型不严格）

- `tryon: "false"` → 被当作 false
- **根因**：Pydantic 默认 bool 转换宽松，数字 0/1 和字符串 "true"/"false" 会被自动转换
- **风险**：调用方误传非 bool 类型可能导致意外触发试穿，产生高延迟
- **建议**：使用 `StrictBool` 或 `Field(strict=True)` 拒绝非 bool 类型

## 六（B）、鉴权测试

| BV-60 | recommend 空 `Authorization:` | 200 | 2.94s | ⚠️ 需关注 | 6 套搭配 |
| BV-61 | GET outfits 列表无认证 | 200 | 0.07s | ⚠️ 需关注 | 返回 outfits 数据，**可随意爬取** |
| BV-62 | GET sku 详情无认证 | 200 | 0.06s | ⚠️ 需关注 | 返回完整 SKU 信息（含 search_text） |
| BV-63 | regenerate-reason 无认证 | 200 | 1.27s | ⚠️ 需关注 | 生成 118 字理由，**可无限制调用** |

**结论与问题：**

**⚠️ 问题 ISS-05：接口完全没有鉴权**
- 所有接口（recommend / regenerate-reason / GET outfits / GET sku）均无任何鉴权机制
- `Authorization`、`X-API-Key` 等认证头被完全忽略
- app_id 只校验是否为空，不校验值（见 ISS-04）
- 任何人只要能访问到服务地址，即可无限制调用，消耗 LLM 资源
- GET 接口可随意爬取 outfits 列表和 SKU 详情
- **风险**：资源滥用、数据爬取、无法限流追责
- **建议**：
  1. 增加 API Key 认证，请求头校验 `X-API-Key`
  2. app_id 白名单校验
  3. 按 app_id/API Key 维度限流
  4. 文档补充认证方式说明

## 八、边界测试结论

### 8.1 通过项（71/94）

1. **类型校验**：null 和数字类型的 app_id/outfit_id/message/reason_style 均被 422 正确拒绝；tryon=null 也被 422 拒绝
2. **空值处理**：空串和纯空格在 app_id/sku_id/message 中均被正确 strip 并视为无效
3. **超长输入**：所有字段（app_id/sku_id/message/session_id/reason_style/outfit_id）均无长度限制，不报错
4. **特殊字符**：中文/emoji/HTML 标签/多语言/零宽字符/BOM 均安全透传，无注入风险
5. **安全防护**：SQL 注入和 XSS 均安全，返回空结果或 404，无执行风险
6. **降级策略**：image_url 各种异常（空串/非 http/非图片/404）均正确降级到 sku 锚点，不产生 500
7. **请求体结构**：多余字段被忽略，非 object 被拒绝
8. **错误响应格式**：所有错误响应均包含 code/message/trace_id 三字段，格式一致
9. **不合法 SKU 安全性**：SPU/截断/小写/特殊字符等格式异常的 SKU 均安全返回空列表，不报错、不注入
10. **reason_style 安全性**：emoji/中文/SQL 注入/XSS/零宽字符均安全透传，数字/数组/对象类型被 422 拒绝
