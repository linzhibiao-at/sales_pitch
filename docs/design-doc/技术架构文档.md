## 1. 项目概述

FILA 营销话术生成服务（`sales_pitch`）是一个面向导购的 AI 话术生成平台。导购通过 API 提交**顾客画像**和**商品信息**，系统调用 LLM 生成可直接发送给顾客的个性化营销话术。

核心能力：

- **千人千面**：根据顾客性别、年龄段、风格偏好、使用场景等特征定制话术切入点
- **多轮会话**：同一 `session_id` 内记住之前的推荐和反馈，支持话术迭代调整
- **上下文压缩**：对话历史超 5 万 token 时自动摘要压缩，避免上下文膨胀
- **双通道 LLM**：DashScope 主通道 + 安踏 AI 网关 fallback，LangChain 原生降级
- **请求审计**：所有请求/响应落库 MySQL（`request_audit` 表），支持按 trace_id 联查

## 4. 核心组件详解

### 4.1 路由层（`routers/`）

#### `sales_pitch.py` — 话术生成路由

| 职责 | 说明 |
|---|---|
| Agent 初始化 | 模块导入时执行 `_init_agent_stack()`：Redis → LLM → Agent → Service |
| 降级策略 | Redis 不可用 → `_pitch_svc = None` → 请求返回 503 |
| 请求处理 | app_id 白名单校验 → API Key 绑定校验 → `service.generate()` → 返回结果 |

#### `audit.py` — 审计查询路由

独立于 Agent 服务，创建独立的 `RequestAuditLogger` 实例。提供列表查询（`/v1/audit/requests`，page/offset 分页 + total 总数）和详情查询（`/v1/audit/requests/{trace_id}`）。

#### `user.py` — 用户信息路由

占位路由，`GET /v1/users/me` 返回随机 UUID。

---

### 4.2 服务层（`services/`）

#### `SalesPitchService`

核心编排类，职责：

1. **文本块构建**：三个纯函数将 Pydantic 入参转为中文 prompt 文本块
   - `build_customer_block()` — 顾客画像 → 【顾客信息】
   - `build_products_block()` — 商品清单 → 【商品信息】
   - `build_requirements_block()` — 风格/渠道/字数 → 【话术要求】
2. **Agent 调用**：拼装用户消息 → `agent.ainvoke()` → 提取最后一条 AI 消息
3. **会话映射**：`session_id` → LangGraph `thread_id`，同 session 自动共享对话历史
4. **审计落库**：`finally` 块中调用 `_write_audit()`，MySQL 关闭/失败均静默

```python
# 核心调用流程
config = {"configurable": {"thread_id": session_id}}
agent_result = await self._agent.ainvoke(
    {"messages": [{"role": "user", "content": user_msg}]},
    config=config,
)
# 提取最后一条 AI 消息作为话术
for msg in reversed(agent_result["messages"]):
    if msg.type == "ai" and msg.content:
        pitch = msg.content.strip()
        break
```

### 4.3 Agent 层（`agent/`）

#### `loader.py` — 资源加载 + Agent 构建

**启动时加载流程**：

```
load_resources(store)
  ├── load_agents(store)     → AGENTS.md  → /memory/AGENTS.md
  ├── load_skills(store)     → SKILL.md   → /skills/sales-pitch/SKILL.md
  └── load_souls(store)      → SOUL.md    → /soul/warm, /soul/professional, /soul/concise
```

所有资源存入 RedisStore，命名空间固定为 `("fileSystem",)`。

**Agent 构建**（`build_agent()`）：

```python
agent = create_deep_agent(
    model=llm,                    # LangChain 双通道 fallback 链
    system_prompt="你是 FILA 品牌的金牌导购顾问...",
    skills=["/skills/"],          # 从 Store 加载 Skill 定义
    middleware=[
        AlwaysLoadMemoryMiddleware,  # 每次 invoke 重新加载 AGENTS.md
        SummarizationMiddleware,     # token > 50000 时自动压缩
    ],
    permissions=[FilesystemPermission(deny write, /skills/** /memory/** /soul/**)],
    backend=store_backend,
    store=store,
    checkpointer=checkpointer,
)
```

#### `middleware.py` — 自定义记忆中间件

`AlwaysLoadMemoryMiddleware` 继承 DeepAgent 的 `AgentMiddleware`，**去掉原版的跳过逻辑**：

| 对比 | 原版 MemoryMiddleware | AlwaysLoadMemoryMiddleware |
|---|---|---|
| `before_agent` | `if "memory_contents" in state: return None` | 每次从 Store 重新下载 |
| 效果 | 同 thread_id 第二次调用不刷新记忆 | 每次调用都加载最新 AGENTS.md |

### 4.4 LLM 工厂层（`llm/`）

#### `factory.py` — 双通道 LLM

```
create_sales_pitch_llm()
  ├── primary:  ChatOpenAI(dashscope, qwen-plus)
  │               └── with_fallbacks([fb])
  └── fallback: ChatOpenAI(安踏网关, qwen3.5-flash)

create_summarization_llm()
  └── ChatOpenAI(dashscope, qwen-turbo)   # 压缩用便宜模型，不走 fallback
```

| 通道 | 模型 | 用途 | API Key 环境变量 |
|---|---|---|---|
| 主通道 | `qwen-plus` (DashScope) | 话术生成 | `DASHSCOPE_API_KEY` |
| Fallback | `qwen3.5-flash` (安踏网关) | 主通道失败时降级 | `ANTA_LLM_API_KEY` |
| 压缩 | `qwen-turbo` (DashScope) | 上下文摘要 | 复用 `DASHSCOPE_API_KEY` |

使用 LangChain 原生 `.with_fallbacks()` 实现透明降级，替代原手写 httpx 重试 + 模型链逻辑。

### 4.5 基础设施层（`infra/`）

#### `redis.py` — Redis 初始化

```python
def init_redis():
    redis_client.ping()                        # 验证连通性
    checkpointer = RedisSaver(prefix="sp_checkpointer")  # 短期记忆（对话 checkpoint）
    store = RedisStore(prefix="sp_store")                 # 长期记忆（文件存储）
    store_backend = StoreBackend(store, namespace=lambda _: ("fileSystem",))
    return redis_client, checkpointer, store, store_backend
```

| 组件 | 用途 | Redis Key 前缀 |
|---|---|---|
| `RedisSaver` | LangGraph 对话 checkpoint（thread_id → 消息历史） | `sp_checkpointer` |
| `RedisStore` | DeepAgent 文件存储（skills/memory/soul） | `sp_store` |

#### `mysql.py` — MySQL 审计客户端

```python
class MysqlClient:
    """pymysql 客户端，自动建表 + 单连接（线程安全锁保护）。"""
    # 启动时 CREATE TABLE IF NOT EXISTS request_audit（utf8mb4）
    insert_audit(doc)          # 审计写入，返回自增 ID
    query_audit(where, params, limit, offset)  # 列表查询（ts 倒序）
    count_audit(where, params) # 总数统计（分页用）
    get_by_trace_id(trace_id)  # 详情查询
```

| 设计点 | 说明 |
|---|---|
| 连接串 | `mysql+pymysql://user:pass@host:port/db?charset=utf8mb4`，`MYSQL_URL` 环境变量优先 |
| 自动建表 | 启动时执行 `CREATE TABLE IF NOT EXISTS`，无需手工建表 |
| 表结构 | 索引列（trace_id/session_id/app_id/ts）+ JSON 列（input/intent/recall/ranking/result 存 TEXT/LONGTEXT） |
| 静默降级 | url 为空或连接失败 → `available=False` → 审计写/查均返空，不影响主链路 |
| 连接模型 | 单连接 + `threading.Lock` 串行化；uvicorn 多 worker 时各进程独立连接 |

### 4.6 鉴权与限流（`auth.py`）

| 组件 | 职责 |
|---|---|
| `ApiKeyStore` | 从 `config/api_keys.yaml` 加载 Key 白名单，支持 mtime 热加载 |
| `RateLimiter` | per app_id 的 QPM（分钟桶）+ 日调用量（天桶）限制 |
| `ConcurrencyLimiter` | per app_id 的并发槽 + 排队队列（`asyncio.Semaphore`） |
| `verify_api_key()` | FastAPI Depends：Key 校验 → allowed_apis → 限流 → 并发排队 → yield → 释放 |

排队信息注入 `request.state.queue_info`，由 `trace_id_middleware` 回写到 `X-Queue-*` 响应头。

### 4.7 数据模型（`models.py`）

| 模型 | 关键字段 | 验证逻辑 |
|---|---|---|
| `SalesPitchCustomerInfo` | nickname, gender, age, style_preference, scene, extra | HTML 标签剥除、lone surrogate 清理 |
| `SalesPitchProductInfo` | title, sku_id, price, selling_points, extra | title 非空（清理后校验）、HTML 清理 |
| `SalesPitchRequest` | session_id, app_id, customer, products[1-10], pitch_style, channel, max_length | products 数量约束、负数 max_length 拒绝 |

## 5. 请求处理全链路

```
HTTP POST /v1/sales-pitch/generate
  │
  ├── ① trace_id_middleware：生成 trace_id → request.state
  ├── ② debug_api_request_middleware：记录 POST 入参（脱敏）
  ├── ③ verify_api_key()：Key 校验 → 限流 → 并发排队
  │
  ▼
  v1_sales_pitch_generate()
  │
  ├── ④ app_id 白名单校验
  ├── ⑤ API Key 绑定校验（app_id 须与 Key 绑定的 app_id 一致）
  │
  ▼
  SalesPitchService.generate()
  │
  ├── ⑥ build_customer_block() + build_products_block() + build_requirements_block()
  ├── ⑦ agent.ainvoke({"messages": [...]}, config={"thread_id": session_id})
  │       │
  │       ├── AlwaysLoadMemoryMiddleware：从 RedisStore 加载 AGENTS.md
  │       ├── SummarizationMiddleware：检查 token 数，超限则压缩
  │       ├── LangChain fallback 链：DashScope → 安踏网关
  │       └── 返回 messages 列表
  │
  ├── ⑧ 提取最后一条 AI 消息作为话术
  └── ⑨ _write_audit()：审计文档 → MySQL request_audit 表（静默降级）
  │
  ▼
  响应：{"session_id", "pitch", "pitch_style", "model", "trace_id"}
  └── X-Trace-Id / X-Queue-Status / X-Queue-Wait 响应头
```

### 7.2 环境变量

| 变量 | 用途 | 默认值 |
|---|---|---|

`load_config()` 采用 **mtime-based 缓存**：每次调用比较 `config.yaml` 的文件修改时间，未变化则返回缓存 dict，修改后自动重新加载。`api_keys.yaml` 同理。

## 8. Agent 资源管理

Agent 资源文件位于 `.sales_pitch/` 目录，启动时加载到 RedisStore：

| 文件 | Store Key | 用途 |
|---|---|---|
| `AGENTS.md` | `/memory/AGENTS.md` | 角色定义：FILA 金牌导购 + 工作原则 + 多轮规则 |
| `SOUL.md` | `/soul/{name}` | 话术风格：warm / professional / concise |
| `skills/sales-pitch/SKILL.md` | `/skills/sales-pitch/SKILL.md` | 话术撰写要求 + 风格适配 + 不适用场景 |

**热更新**：修改 `.sales_pitch/` 下的文件后，重启服务即生效（启动时重新加载到 RedisStore）。`AlwaysLoadMemoryMiddleware` 确保每次 Agent 调用都读取最新的记忆内容。

## 11. 风险与降级策略

| 风险场景 | 降级策略 |
|---|---|
| **Redis 不可用** | `_init_agent_stack()` 捕获异常 → `_pitch_svc = None` → 请求返回 503 |
| **DashScope 失败** | LangChain `.with_fallbacks()` 自动切换到安踏 AI 网关 |
| **安踏网关也失败** | 两层均失败 → Agent 抛异常 → 503 + 审计记录 error |
| **Agent 空输出** | 检测到最后一条消息为空 → `{"error": "..."}` → 503 |
| **MySQL 不可用** | 审计写/查静默降级（`available=False`），不影响话术主链路 |
| **上下文膨胀** | `SummarizationMiddleware` 超 5 万 token 自动压缩，保留最近 10 条 |
| **API Key 泄露** | `redact_for_log()` 递归脱敏 api_key 字段 |

## 12. API 接口

### POST `/v1/sales-pitch/generate`

**入参**：

```json
{
  "session_id": "optional-session-id",
  "app_id": "micro_guide",
  "customer": {
    "nickname": "王女士",
    "gender": "女",
    "age": "35",

    "scene": "秋季通勤"
  },
  "products": [
    {
      "sku_id": "U2D240211",
      "title": "FILA 经典卫衣",
      "price": 399,
      "selling_points": "重磅面料; 经典LOGO"
    }
  ],
  "pitch_style": "warm",

  "max_length": 120
}
```

**出参**（成功）：

```json
{
  "session_id": "optional-session-id",
  "pitch": "王女士，这件卫衣真的特别适合您...",
  "pitch_style": "warm",
```

**出参**（失败）：

```json
{
  "code": 503,
  "message": "agent service unavailable (Redis or LLM init failed)",
  "trace_id": "abc123..."
}
```

### GET `/v1/audit/requests`

审计列表查询，支持 `trace_id` / `app_id` / `session_id` / `request_kind` / `status` / `ts_from` / `ts_to` 过滤，`page`（1 起）或 `offset` 分页（page 优先），`size` 上限 200。返回 `{enabled, total, items}`，列表项为精简行（含 `pitch_style`、`pitch` 前 80 字）。

### GET `/v1/audit/requests/{trace_id}`

审计详情查询，返回完整文档（含完整 `input` / `result` JSON 块）。审计关闭时 503，未命中 404。

### GET `/health`

```json
{"status": "ok", "service": "sales_pitch"}
```
