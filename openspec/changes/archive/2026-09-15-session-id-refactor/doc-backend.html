二、需求一：session_id 确定性生成

2.1 需求回顾

  • 入口：POST /v1/sales-pitch/generate
  • 当前问题：session_id 由调用方传入或由系统 uuid.uuid4().hex 随机生成，与导购身份和会员身份无关联，同一导购服务同一会员的多次对话无法自动共享上下文
  • 期望行为：
    • 请求体不再接受 session_id 字段
    • 系统根据 guide_num 和 customer.union_id 自动拼接生成 session_id，格式 {guide_num}_{union_id}
    • 相同导购 + 相同会员 → 相同 session_id → LangGraph 对话历史自动累积共享
    • 不同导购或不同会员 → 不同 session_id → 对话上下文相互独立
    • session_id 在响应体中返回，在审计日志中记录

2.2 方案说明

  1. 删除 SalesPitchRequest.session_id 字段：Pydantic 模型中移除该字段，调用方传入的 session_id 被 Pydantic 默认行为忽略（extra="ignore"）
  2. session_id 生成逻辑：在 SalesPitchService.generate() 方法中，将原来的 session_id = (req.session_id or "").strip() or uuid.uuid4().hex 替换为 session_id = f"{req.guide_num}_{req.customer.union_id}"。由于 guide_num 和 union_id 均为必传且空白已在模型层剥离，此处无需额外防御
  3. session_id 作为 LangGraph thread_id：生成逻辑不变，仍然 config = {"configurable": {"thread_id": session_id}}，复用 Redis checkpointer 持久化对话历史
  4. 响应体仍返回 session_id：调用方可用于展示或调试，但不可用于覆盖
  5. 审计日志记录确定性 session_id：_write_audit 中的 session_id 字段直接使用生成值
为什么用下划线分隔？ 下划线在 Redis key、URL、日志中均无需转义，比冒号兼容性更好。guide_num（工号，数字/字母）和 union_id（平台标识）本身不含下划线，不存在歧义。

三、需求二：导购标识全局重命名（guide_id → guide_num）

3.1 需求回顾

  • 当前状态：guide_id 为可选字段，用于导购身份校验，与 session_id 正交
  • 期望变更：
    • 全代码库和配置文件中 guide_id 统一重命名为 guide_num，更准确表达"导购工号"的业务含义
    • guide_num 改为必传（因为 session_id 生成依赖它）
    • guide_auth.enabled 开关仅控制存在性校验，不再控制字段是否必传
    • 原有校验逻辑（存在性校验、开关控制、鉴权顺序）不变

3.2 方案说明

  1. Pydantic 模型层（backend/models.py）：
    • SalesPitchRequest.guide_id: Optional[str] → guide_num: str（Field(min_length=1)）
    • _strip_text validator 字段列表从 "guide_id" 改为 "guide_num"
  2. 导购校验模块（backend/guide_auth.py）：
    • verify_guide_identity(guide_id) → verify_guide_identity(guide_num)
    • GuideUserStore.get(guide_id) → GuideUserStore.get(guide_num)
    • 错误信息 "guide_id required" → "guide_num required"，"guide not found" 不变
  3. 配置解析（backend/config.py）：get_guide_auth_config 解析 guide_num key
  4. 配置文件（config.yaml）：guide_auth.users 条目 key 从 guide_id 改为 guide_num
  5. 路由层（backend/routers/sales_pitch.py）：body.guide_id → body.guide_num
  6. 审计日志（backend/services/sales_pitch_service.py）：input 块 "guide_id" → "guide_num"
  7. OpenSpec 主 spec（openspec/specs/guide-identity/spec.md）：所有 guide_id 替换为 guide_num
