# 设计：精简「话术生成」输入（控制台表单 + 接口契约）

## Context

- 控制台 `web/src/views/GenerateView.vue` 上一轮刚扩展为"接口能力全集"表单（新增会员等级/积分、促销与优惠区块、分享方式、四档语气、券三态等控件）。
- 前后端同步收敛：同样的 12 个字段（size_info / style_preference / scene / budget / notes、sku_id / price / category / material / selling_points、share_mode、channel）从控制台表单与后端入参契约一并移除；后端此前已实现的相关能力（share_mode 结构区分、渠道映射）随之回退。
- 参见 proposal.md「Why」：控制台侧——字段全集拉低联调与试跑效率、「导购工号」归属混淆；接口侧——入参携带业务已不再使用的字段，提示词注入与审计冗余。

## Goals / Non-Goals

**Goals:**

- 表单聚焦核心字段：导购信息（工号）、顾客信息（6 字段）、商品信息（名称 + 颜色）、促销与优惠、话术要求（风格 / 字数 / 补充要求）
- 导购工号归属修正：独立区块、置于表单最上方
- 请求构造与请求摘要徽章同步清理，无残留字段
- 后端入参契约收敛到同一核心集：模型、提示词块、审计快照、提示词资产、接口文档全线一致

**Non-Goals:**

- 不新增任何字段；promotions / coupon_names / member_level / points / 四档语气 / extra_prompt 等保留能力不回改
- 不回溯修改审计历史数据、PRD 文档与历史变更记录
- 不为被移除字段保留「拒绝传参」策略（不引入 422 校验）

## Decisions

### D1: 导购工号独立为「导购信息」区块并置顶

- 选择：新增「导购信息」卡片（单一必填输入框：导购工号），置于表单最上方、先于「顾客信息」。
- 备选：① 并入页面顶部 header（与 session 栏同行）；② 移到「设置」页作为全局配置。
- 理由：联调时需频繁切换工号，留在表单即改即用；独立卡片与现有卡片体系一致。设置页方案会让切换多一跳（已与用户确认选择独立区块）。
- 持久化保持 `sp_guide_num` localStorage（既有行为），canSubmit 必填校验与提示文案不变。

### D2: 商品「颜色」保留

- 选择：商品信息保留「商品名称 + 颜色」两个控件。
- 理由：颜色是服装话术常用卖点；用户删除清单未包含颜色（已与用户确认）。

### D3: 前后端同步收敛（原「仅前端清理」决策作废）

- 选择：同一批字段从控制台表单、后端 Pydantic 模型、提示词块构建、审计快照、提示词资产与接口文档中一并移除。
- 理由：字段已无业务消费方（微导购核心集不含它们）；仅隐藏 UI 而保留契约会让「表单子集」与「接口全量」长期分叉，提示词与审计继续承载无用信息。用户明确要求「后端接口入参也要跟着调整」。
- 代价：这些字段不再具备任何测试路径；相应接口级测试改写为「传入被忽略」的兼容用例。

### D4: 请求摘要徽章与样式同步收缩

- 删除：share_mode 徽章与 `shareModeLabel` helper（控制台不再发送该字段）；`main.css` 的 `.badge-purple`（失去唯一引用）。
- 保留：话术风格（绿）、活动×N（青）、券数/无券（灰）徽章。
- 商品徽章 key 由 `p.sku_id || p.title` 简化为 `p.title`。

### D5: 表单状态与请求构造的清理方式

- `form.customer` 仅保留 6 个键；`defaultProduct()` 收缩为 `{ title, color }`；`form` 顶层删除 `share_mode`、`channel`；`pitch_style` 默认值与其余逻辑不动。
- `doGenerate` 中：customerRaw 空值过滤逻辑不变（union_id 强制保留）；products 映射仅保留 title/color；payload 删除 share_mode/channel 条件展开；请求快照同构清理。

### D6: 契约收敛语义——直接删除 + 静默忽略

- 选择：被移除字段直接从 Pydantic 模型删除；若仍被传入，沿用默认 `extra` 忽略语义——请求正常处理，字段不进入提示词与审计。
- 备选：① `extra="forbid"` 显式 422 拒绝（打断存量调用方，与项目「剥除降级」的既有风格相悖）；② 保留字段但不再注入提示词（契约继续误导、审计仍记录无效字段）。
- 理由：模型未配置 `model_config`，默认即 ignore；删字段天然获得「兼容降级」，无需额外代码。测试以「携带全套旧字段的请求成功且无残留」固化该行为。

### D7: share_mode 的规格承接与归档顺序

- `share_mode` 是上一变更（`add-ai-invite-copy-inputs`，已实现未归档）新增的能力；本次回退以规格增量承接：本变更新增 `specs/ai-invite-copy-inputs/spec.md`（REMOVED share_mode 需求 + MODIFIED 审计快照需求）。
- 归档顺序要求：须先归档 `add-ai-invite-copy-inputs`（其 delta 生成主规格），本变更归档时 REMOVED/MODIFIED 才有承接对象。
- 迁移语义：调用方停用 `share_mode`（残留传参被忽略）；需要单品/成套差异化结构时改用 `extra_prompt` 补充要求表达。

### D8: 资产与文档同步范围

- 提示词资产：`SKILL.md` 删除「分享方式与结构」「按渠道调整表达」两节，执行流程与撰写要求中相应表述随字段收敛更新；`AGENTS.md` 删除「分享方式」工作原则与对已删字段的引用。
- 接口文档：`.qoder/reference/api-spec.yaml`（三个 schema）、根 `README.md`（示例与字段表）、`docs/design-doc/技术架构文档.md` §4.7 数据模型表（一次修正为当前真实字段集）。
- 控制台：`AuditView.vue` 移除分享方式展示行与 `shareModeLabel`（新审计不再记录该字段；历史记录中的数据不再单独展示）。

## Risks / Trade-offs

- [旧调用方仍传被移除字段] → 静默忽略、请求不受影响（D6）；未来如需强制升级可另立变更收紧
- [share_mode 为微导购刚对接的字段，若其仍依赖单品/成套差异化结构] → 迁移路径：改用 `extra_prompt` 表达（D7）；实施前与调用方确认
- [工号置顶改变操作动线（先填工号再填顾客）] → 与 session 生成逻辑（guide_num + union_id）语义一致，可接受
- [移除价格/类目/材质/卖点后商品描述能力变弱] → 与精简诉求一致；需要补充描述时走「补充要求」自由文本
- [历史 localStorage 中 `sp_guide_num` 已有值] → 继续自动回填，无迁移成本

## Migration Plan

- 前后端同步变更：前端重新构建（或 Vite 热更新）即生效；后端重启后新契约生效；无数据迁移（审计历史数据保持原样，新增记录不再含被移除字段）；localStorage 键（`sp_guide_num` / `sp_app_id` 等）不变
- 发布顺序：先发后端（忽略旧字段，兼容降级）再发前端，或同时发布；任意顺序均安全（纯收窄）
- 回滚：还原对应文件即可恢复能力；期间传入被忽略的字段不可追溯（可接受）
- 归档顺序：先归档 `add-ai-invite-copy-inputs`，再实施本变更、最后归档本变更（见 D7）
